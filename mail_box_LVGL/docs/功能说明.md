# 项目功能说明文档

> 适用版本：死代码清理后（2026-08-12）
> 项目：GEC6818 智能快递柜嵌入式端（C + LVGL，交叉编译目标 arm-linux）

---

## 一、整体架构

项目采用 **「逻辑包装层 + LVGL UI 实现层」** 的分层结构：

```
main.c（主流程/状态机）
   ├── 包装层（业务逻辑 + LVGL调用）：login_page / store_page / takeout_page / query_page
   │        └── UI 实现层（LVGL 界面）：lvgl_login_page / lvgl_store_page / lvgl_takeout_page
   │                                     lvgl_query_page / lvgl_overlay_page / lvgl_main_menu
   ├── 后台服务：pickup_monitor（扫码监控）/ weather_utils（天气）/ net_client（NTP 时间）
   ├── 网络通信：net_client（HTTP） / verify_gate（云端验证网关）/ sms（短信）
   ├── 数据模型：data_store（储物柜链表 + 用户文件）
   └── 平台驱动：input（触摸输入）/ display（LCD 显示）
```

调用关系要点：
- 每个界面模块由 **包装层 `.c`**（业务状态机，如登录成功/失败/超时判断）与 **LVGL 层 `lvgl_*.c`**（纯界面元素创建/销毁/按键事件）组成。
- 界面切换遵循 **LOAD NEW → DELETE OLD**（Pending-Delete）机制：先创建新页面，再删除旧页面，避免 `act_scr=NULL` 段错误。
- 扫码取件通过全局标志 `g_pickup_notify_flag` 通知所有界面层（各页面等待循环中检查并中断返回 `RET_SCAN_PICKUP`）。

## 六、核心流程要点

### 快递员存件
```
主菜单(3) → show_sendman_login（lvgl_login_page）→ show_store_info（lvgl_store_page）
  → 选箱型/时长 → 查空柜（locker_find_first_empty_by_prefix）→ 分配柜
  → 生成 pickup_token → show_pay_info（lvgl_overlay）→ show_send_success → 继续/返回
```

### 用户取件（含扫码）
```
主菜单(1) → vg_create_pickup 生成 token → generate_qr 生成二维码 → lvgl_takeout_create
  → 输入 4 位码验证（locker_find_by_code + locker_clean_by_id）
  → 或用户扫码：pickup_monitor 轮询 → g_pickup_notify_flag → check_scan_pickup 开箱
```

### 快件查询
```
主菜单(4) → show_received_query（lvgl_query_page）→ 短信验证 → 遍历柜链表
  → 有包裹：had_received.sjpg + 取件码；无包裹：canvas "No Box"
```

## 七、注意事项

1. 所有图片路径为绝对路径 `/Workspace/mail_box_pic/resource/...`，部署时资源必须位于该目录。
2. LVGL 加载图片需 .sjpg 扩展名（SJPG 解码器只认 sjpg），非 LVGL 场景（二维码）用普通 JPG + libjpeg。
3. 界面销毁必须走 Pending-Delete（先建新后删旧），回调中需判空 `s_ui`。
4. 二维码生成后必须检查 `generate_qr` 返回值，失败时不可加载图片。
5. 触摸设备 /dev/input/event0 被 touchpad 线程与 LVGL evdev 共享，通过 `touchpad_set_reading` 协调，不可同时读取。
